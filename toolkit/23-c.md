# C

## Language block (paste after the session primer)

```text
C CONVENTIONS for this conversation:
- Standard: {{C11 / C17}}. Compiler: {{gcc / clang / MSVC}} on {{platform}}. Build: {{make / CMake}}.
- Code must compile cleanly with -Wall -Wextra -Wpedantic {{-Werror}} (or /W4 on MSVC).
- No undefined behavior: check for signed overflow, out-of-bounds access, use of uninitialized values,
  strict aliasing, NULL dereference, use-after-free and double free. If code relies on
  implementation-defined behavior, say so.
- Memory: every allocation has one clear owner and a matching free on every path, including the error
  paths (use a single cleanup label with goto if that is the house style). Check every malloc/calloc/realloc
  result. Never assign realloc's result straight back to the same pointer.
- Strings and buffers: always pass a buffer size; use snprintf, never sprintf/strcpy/strcat/gets. Use
  size_t for sizes and indices. Watch for off-by-one errors with the NUL terminator.
- Errors: return error codes (or a status enum), with outputs written through pointer parameters. Check
  the return value of every library call (fopen, fread, write...). Document errno usage.
- const-correctness on pointer parameters. static for file-local functions and data.
- Headers: include guards (or #pragma once if the project uses it), only declarations, minimal includes.
- Prefer clear code to clever macros. Macros: parenthesize every argument and the whole body; use
  do { } while (0) for statement-like macros.
- Tests: {{Unity / CMocka / plain assert-based test binary}}. Recommend running them under
  AddressSanitizer + UndefinedBehaviorSanitizer (-fsanitize=address,undefined) or Valgrind.
- No new dependencies without asking.
```

## C prompts

### Memory bug / crash

````text
My C program {{crashes with SIGSEGV / corrupts data / leaks memory / aborts with a double free}}.
Sanitizer / Valgrind / debugger output:
```
{{paste ASan/UBSan/Valgrind report or gdb backtrace (bt full)}}
```
Code (the functions in the trace + the allocation and free sites):
{{code}}

1) Say which access is invalid and why, citing the allocation, free and access sites from the report.
2) Find the root cause: ownership, lifetime, size calculation, or off-by-one.
3) Give the minimal fix, and check that the other code paths (especially error paths) don't have the same bug.
````

### Undefined behavior review

```text
Review this C code for undefined behavior and portability problems:
signed overflow, shifts by >= width or by negative amounts, out-of-bounds access, uninitialized reads,
strict aliasing violations, misaligned access, sequence-point problems, NULL dereference, invalid
pointer arithmetic, format-string mismatches, and integer promotion / sign-conversion surprises.
For each one: the line, why it's UB (or implementation-defined), a concrete input that triggers it,
and the fix.
{{code}}
```

### Safe string / buffer handling

```text
Rewrite this code so that all string and buffer handling is bounds-safe:
- Pass explicit sizes; use snprintf and check its return value for truncation.
- No strcpy/strcat/sprintf/gets/scanf("%s").
- Handle the NUL terminator explicitly. Use size_t for lengths.
Keep the behavior otherwise identical, and list every place where the old code could overflow.
{{code}}
```

### Error-handling and cleanup

```text
Make the error handling in this function robust:
- Check every allocation and library call.
- Release all resources on every exit path (single cleanup label with goto, the reverse order of acquisition).
- Return a meaningful error code; outputs only through pointer parameters, set only on success.
{{code}}
```

### Design a module API

```text
Design a C module (header + implementation) for {{purpose}}.
- An opaque struct (typedef struct foo foo;) with create/destroy functions; the caller owns the result.
- Every function returns a status code; outputs go through pointer parameters.
- Document ownership and lifetime for every pointer parameter and return value in the header.
- Not thread-safe unless I ask otherwise; say so in the header.
Give foo.h, foo.c and a test file.
```

### Makefile / CMake

```text
Create a {{Makefile / CMakeLists.txt}} for this C project:
sources {{list or layout}}, target {{executable/library name}}, standard {{C17}}.
- Warnings: -Wall -Wextra -Wpedantic (MSVC: /W4).
- Debug build with -g -O0 -fsanitize=address,undefined; release build with -O2.
- A test target that builds and runs the tests.
Keep it minimal and explain each non-obvious line.
```
